# 따릉이 실시간 대여정보 API (OA-15493)

서울 열린데이터광장 Open API. 대여소별 현재 자전거 재고를 돌려준다.

- 데이터셋: [서울시 공공자전거 따릉이 실시간 대여정보](https://data.seoul.go.kr/dataList/OA-15493/A/1/datasetView.do)
- 서비스명: `bikeList`
- 갱신 주기: 실시간 (**과거 데이터는 제공하지 않음** → 저장하지 않은 시점은 영구 손실)
- 라이선스: 공공누리 1유형 (출처표시, 상업적 이용·변경 가능)

## 요청

```
http://openapi.seoul.go.kr:8088/{KEY}/{TYPE}/{SERVICE}/{START_INDEX}/{END_INDEX}/[{stationId}]
```

예: `http://openapi.seoul.go.kr:8088/{KEY}/json/bikeList/1/1000/`

| 변수 | 타입 | 필수 | 설명 | 값 |
|---|---|---|---|---|
| `KEY` | String | O | 인증키 | 열린데이터광장에서 발급 |
| `TYPE` | String | O | 응답 형식 | `xml` / `json` |
| `SERVICE` | String | O | 서비스명 | `bikeList` |
| `START_INDEX` | Integer | O | 요청 시작 위치 (페이징 시작 번호, 데이터 행 기준) | 정수 |
| `END_INDEX` | Integer | O | 요청 종료 위치 (페이징 끝 번호) | 정수 |
| `stationId` | String | X | 대여소 ID | 예: `ST-4` (**미검증**) |

**주의:** 인증키가 URL 경로에 들어간다. 로그·예외 메시지·에러 알림에 URL이 그대로 찍히면 키가 노출되므로 출력 전에 마스킹한다.

## 응답 (JSON)

최상위 키는 `rentBikeStatus`.

| 필드 | 설명 | 실제 값 타입 | 성격 |
|---|---|---|---|
| `list_total_count` | 총 데이터 건수 (정상 조회 시 출력) | 정수 | 아래 "관측" 참고 |
| `RESULT.CODE` | 요청 결과 코드 | 문자열 | 아래 메시지표 |
| `RESULT.MESSAGE` | 요청 결과 메시지 | 문자열 | |
| `row[].stationId` | 대여소 ID (예: `ST-4`) | 문자열 | 키 |
| `row[].stationName` | 대여소 이름 | 문자열 | 차원 |
| `row[].stationLatitude` | 위도 | 문자열 | 차원 |
| `row[].stationLongitude` | 경도 | 문자열 | 차원 |
| `row[].rackTotCnt` | 거치대 개수 | 문자열 | 준차원 (가끔 변함) |
| `row[].parkingBikeTotCnt` | 자전거 주차 총 건수 (거치된 자전거 수) | 문자열 | **사실** (매번 변함) |
| `row[].shared` | 거치율 | 문자열 | 파생값 |

응답 예 (2026-11-19 호출, 1~3번 행 중 첫 행):

```json
{
  "rentBikeStatus": {
    "list_total_count": 3,
    "RESULT": {"CODE": "INFO-000", "MESSAGE": "정상 처리되었습니다."},
    "row": [{
      "rackTotCnt": "15",
      "stationName": "102. 망원역 1번출구 앞",
      "parkingBikeTotCnt": "29",
      "shared": "193",
      "stationLatitude": "37.55564880",
      "stationLongitude": "126.91062927",
      "stationId": "ST-4"
    }]
  }
}
```

## 결과 코드

| 코드 | 의미 | 대처 |
|---|---|---|
| `INFO-000` | 정상 처리 | |
| `INFO-100` | 인증키가 유효하지 않음 | 키 확인 |
| `INFO-200` | 해당하는 데이터가 없음 | 범위를 벗어난 페이지 등 (**재현 미검증**) |
| `ERROR-300` | 필수 값 누락 | 요청 인자 확인 |
| `ERROR-301` | 파일타입 값 오류 | `TYPE` 확인 |
| `ERROR-310` | 해당 서비스를 찾을 수 없음 | `SERVICE` 확인 |
| `ERROR-331` | 요청시작위치 값 오류 | `START_INDEX` 확인 |
| `ERROR-332` | 요청종료위치 값 오류 | `END_INDEX` 확인 |
| `ERROR-333` | 요청위치 값의 타입이 유효하지 않음 | 정수로 입력 |
| `ERROR-334` | 종료위치보다 시작위치가 더 큼 | 시작 ≤ 종료 |
| `ERROR-335` | 샘플 키(`sample`)는 한 번에 최대 5건 | 정식 키 사용 |
| `ERROR-336` | 한 번에 1000건 초과 불가 | `END - START + 1 ≤ 1000` |
| `ERROR-500` | 서버 오류 | 지속되면 열린데이터광장 Q&A 문의 |
| `ERROR-600` | 데이터베이스 연결 오류 | 상동 |
| `ERROR-601` | SQL 문장 오류 | 상동 |

수집 코드는 HTTP 200이어도 `RESULT.CODE != "INFO-000"`이면 실패로 취급해야 한다 (오류도 HTTP 200으로 올 수 있는지는 미검증이므로, 코드로 판정하는 쪽이 안전).

## 관측 (직접 호출로 확인, 2026-11-19)

1. **전체 대여소는 2,742개.** `1~1000`, `1001~2000`, `2001~3000`의 3회 호출로 한 스냅샷이 완성된다 (1000 / 1000 / 742행). 고유 `stationId`도 2,742개로 중복 없음.
2. **`list_total_count`는 문서 설명("총 데이터 건수")과 다르게 그 호출에서 돌려준 행 수와 같았다** (1~3 → 3, 1~1000 → 1000, 2001~3000 → 742). 전체 건수 판단에 쓸 수 없다. 마지막 페이지는 **반환 행이 1000개 미만**이라는 조건으로 판단한다.
3. **응답에 수집 시각이 없다.** 호출 시각을 수집 쪽에서 기록해야 시계열이 된다.
4. **모든 값이 문자열**이다 (숫자도 `"15"`). raw는 그대로 두고 형 변환은 dbt staging에서 한다.
5. **`shared`가 100을 넘을 수 있다** (거치대 15개에 29대 → 193). 원천 값이므로 raw에서는 그대로 두고 staging/test에서 다룬다. 같은 대여소(`ST-4`)의 두 시점 값이 29/15 → 193, 19/15 → 127이라서 `shared ≈ round(parkingBikeTotCnt ÷ rackTotCnt × 100)`로 보인다 (표본 2개, 전체 검증은 안 함).
6. **스냅샷 1개의 크기**: JSON 원본 약 0.5MB 추정, gzip 후 약 93KB (2,742개 대여소). 하루 288회면 약 27MB, 한 달 약 0.8GB, 7일 보관분 약 190MB.
7. 데이터셋 페이지의 "대여소 수 1,471개소('18.11월말)"는 옛 수치.

## 미검증 항목

- `stationId` 인자로 단일 대여소 조회
- 범위를 벗어난 `START_INDEX`일 때의 응답 (`INFO-200` 여부와 응답 형태)
- 호출 빈도 제한 여부와 5분 주기 호출 시 서버 측 갱신 주기
- 오류 시 HTTP 상태 코드
